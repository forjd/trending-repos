# trending-repos

A Cloudflare Worker that scrapes [github.com/trending](https://github.com/trending) every 4 hours and serves it as a styled page.

- **Live:** https://trending-repos.danjdewhurst.workers.dev
- **Repo:** `forjd/trending-repos` (public, MIT)

## How it works

```
cron (0 */4 * * *) or POST /__refresh
  → scrape github.com/trending (HTMLRewriter)
  → refuse to publish if it looks broken (< 5 repos, or no stars-today counts)
  → enrich each repo via GitHub REST API (id, topics, homepage, exact counts)
  → append rows to D1 (history), read back badge stats
  → write the snapshot to KV under "latest", unless KV already has a newer one

GET /              → HTML rendered from KV
GET /api/trending  → the KV snapshot as JSON
```

Page loads read only KV. D1 is written and queried only during a scrape.

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Local server on :8787 with local KV and D1. Trigger a scrape with `curl localhost:8787/__scheduled` |
| `npm run typecheck` | `tsc --noEmit` (includes `test/`) |
| `npm test` | Vitest in the Workers runtime, with local KV and D1 and migrations applied. `fetch` is mocked, so no network |

## Deploying

Deploys run from the `ai-agent` VM with `npm run deploy`, using the wrangler OAuth login stored in `~/.config/.wrangler`. If the login has expired, run `npx wrangler login --browser=false`, send Dan the URL, and have him paste back the `localhost:8976/oauth/callback?...` URL his browser fails to load. Then `curl` that URL on the VM, using `[::1]` as the host.

The GitHub workflow is manual only, because the repo has no Cloudflare secrets. To deploy on push, add `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repo secrets and uncomment the `push` trigger.

After a deploy that changes data shape, run a scrape so KV picks it up:

```
curl -X POST -H "authorization: Bearer $(grep '^REFRESH_KEY=' .dev.vars | cut -d= -f2-)" \
  https://trending-repos.danjdewhurst.workers.dev/__refresh
```

A new version takes a few seconds to reach every location. A 404 from `/__refresh` right after deploying usually means the old version answered, so retry.

## Secrets

| Name | Where | Notes |
|---|---|---|
| `REFRESH_KEY` | Worker secret, and `.dev.vars` locally | Guards `POST /__refresh` |
| `GITHUB_TOKEN` | Worker secret, and `.dev.vars` locally | Optional. Use a fine-grained token with public read-only access and no permissions. Without it, API lookups are unauthenticated (60/hour, shared with other Workers on the same IP), so most repos miss topics and ids. The page still works |

`.dev.vars` and `.env` are gitignored. Never commit or print their values.

## Data

D1 table `snapshot_repos`: one row per repo per scrape, primary key `(fetched_at, rank)`. History starts on 2026-10-05.

A past row is the same repo if its `repo_id` (GitHub's numeric id, so it survives renames) matches, or its owner and name match ignoring case. `repo_id` is NULL for rows saved before migration 0002, or when the API lookup failed.

Badges are computed at scrape time and stored on each `Repo` in the snapshot:

- `isNew`: first seen today (UTC), and only when history predates today. Otherwise every repo would be "new" on the first day.
- `daysTrending`: distinct UTC days seen. The page shows it from 2 days onward.

## Gotchas

- **The scraper depends on GitHub's HTML** (`article.Box-row` and children). If GitHub changes it, `refresh()` throws and keeps the old data: `/__refresh` returns 502 and the cron run shows as failed in the dashboard. Check the selectors in `src/scrape.ts` first, then refresh `test/fixtures/trending.html`.
- **Enrichment stops at the first rate-limit response.** The remaining repos keep their scraped data.
- **`package.json` overrides the test pool's wrangler and miniflare** to match ours. The pool pins older copies, whose workerd rejects our compatibility date and which carry audit warnings. When bumping wrangler, bump the miniflare override to the version wrangler uses (`npm ls miniflare`), then delete `node_modules` and `package-lock.json` and reinstall. Overrides don't apply to an existing lockfile.
- **Cron changes take minutes to apply.** After deploying a new schedule, the old one can still fire for a few minutes. Use `/__refresh` instead of waiting for a cron.
- **Changing `database_id` gives you a fresh local D1.** Run `npm run db:migrate:local` again.
- **Local dev is subject to the GitHub API's 60-request hourly limit** without a token. Repeated test scrapes hit it quickly, and enrichment then returns 403s. That's expected, and repos keep their scraped data.
- **Killing dev servers:** `pkill -f wrangler` also matches the shell running it if the command line contains "wrangler". Use `pkill -x workerd` or stop the background task.
- **To preview on the VM**, use Tailscale Serve (`tailscale serve --bg --https=8787 http://127.0.0.1:8787`), not localhost links. Turn it off afterwards.
